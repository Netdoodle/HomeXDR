## HomeXDR v0.1.0 (beta)

The first release of HomeXDR: a self-hosted EDR/XDR with a built-in SIEM for homelabs. It
has run on its author's network for weeks, but it is a beta. Expect rough edges and read
the known limitations below before you rely on it.

### What's in it

- **Agents for Windows, Linux and macOS**, without a kernel driver: process, login, file,
  network and DNS telemetry (ETW and the Event Log on Windows, eBPF on Linux, Endpoint
  Security through `eslogger` on macOS), file integrity monitoring and inventory.
- **Detection:** Sigma rules (built in, plus rule repositories you import), behaviour
  detectors on network data, and an alert view with grouping, suppressions and notes.
- **Antivirus:** new programs are checked against a blocklist, threat intel, ClamAV and
  YARA, then stopped and quarantined or only alerted on, per group.
- **Response:** kill process trees, isolate hosts, quarantine and fetch files, collection
  artifacts and fleet-wide hunts, Windows App Control, Microsoft Defender hardening, and
  address blocks pushed to every host's own firewall.
- **Network visibility:** OPNsense firewall logs, Suricata, NetFlow/IPFIX, DHCP and DNS
  resolver history (AdGuard Home, Pi-hole, Technitium), joined to endpoint processes, with
  a device inventory.
- **Search** across every host, Splunk-style, with charts.
- **Notifications** (ntfy, Discord, webhook, email), a daily digest, host groups with
  inherited policy, backups of events to S3-compatible storage, and known-exploited
  software on your hosts.
- **Optional AI analyst** that annotates alerts, or any MCP client through the built-in
  MCP server.
- **Agents away from home:** an optional second agent port for a port forward that only
  enrolled agents can connect to ([docs/away-from-home.md](https://github.com/Netdoodle/HomeXDR/blob/v0.1.0/docs/away-from-home.md)).

### Installing

```bash
git clone --branch v0.1.0 https://github.com/Netdoodle/HomeXDR.git && cd HomeXDR/deploy
cp .env.example .env    # set HOMEXDR_SERVER_NAMES
docker compose up -d
```

Then open `http://<server>:8080`, create the admin account, create an enrollment token
under Settings and copy the install command for each host. Enroll hosts from your own
network.

### Known limitations

- **Console security.** There is no two-factor login and no built-in HTTPS yet. Keep the
  console on your local network, or put it behind your own reverse proxy with HTTPS.
  Two-factor login is next.
- **Unsigned agents.** Windows may show a SmartScreen warning for the agent, and on macOS
  Full Disk Access has to be granted again after an agent update.
- **Open security review findings.** These are being fixed and are listed in the roadmap:
  - On Linux, some labels used for alert suppression (maintenance and SSH session labels)
    can be set by a local user.
  - On Windows, a standard user who creates `C:\ProgramData\HomeXDR` before the agent is
    installed could later change its configuration. Install the agent on machines where
    that folder does not already exist.
  - An executable's cached hash can be kept stale by the file's owner, and a flood of file
    changes in a temp folder can hide a change elsewhere.
  - Importing events back from a backup trusts the backup's contents.
- **Not yet reviewed:** the network sensors, software inventory, enrollment and self-update
  code in the agent, and syslog and NetFlow intake.
- **Upgrades.** Releases in the 0.x series keep your data, but back up the `data` volume
  (and ClickHouse's) before upgrading.
